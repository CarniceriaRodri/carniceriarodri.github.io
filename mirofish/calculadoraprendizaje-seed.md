# Semilla MiroFish — calculadoraprendizaje

## Material que se evalúa

**calculadoraprendizaje** es una calculadora científica educativa en español. La interfaz incluida en la aplicación Android procede del archivo `calculadora-ordenador-indice-corregido.html` y funciona sin conexión.

La pantalla combina una calculadora científica algebraica con un índice de temas y lecciones. Incluye teclas habituales y funciones científicas, ejemplos que se pueden reproducir con «Pruébalo», ejercicios guiados, pistas y una opción para ver el procedimiento. El progreso de los ejercicios se marca visualmente. Se puede cambiar el estilo de etiquetas entre Casio, Texas Instruments y Sharp.

La aplicación intenta enseñar cómo operar una calculadora convencional. Las etiquetas exactas, las funciones secundarias y algunos procedimientos cambian entre modelos.

## Objetivo de la simulación

Simular las expectativas, dudas y reacciones de distintos perfiles de usuarios que estén aprendiendo a usar una calculadora científica. Buscar problemas de comprensión, orientación y accesibilidad que convenga revisar en una prueba real.

**Límite importante:** los agentes de esta simulación no abren ni ejecutan el HTML o el APK y no pulsan botones. Sus comentarios se basan solo en esta descripción; son hipótesis simuladas, no resultados observados ni evidencia de que una función falle.

## Perfiles que se deben simular

Crea perfiles variados, sin tratarlos como estereotipos:

1. Estudiante de secundaria que entiende operaciones básicas y está aprendiendo trigonometría.
2. Persona adulta que vuelve a estudiar y usa una calculadora científica por primera vez.
3. Docente que busca explicar funciones y errores frecuentes.
4. Persona que conoce calculadoras Casio y espera que las teclas secundarias coincidan con su modelo.
5. Persona acostumbrada a Texas Instruments o Sharp.
6. Usuario que necesita instrucciones breves y botones fáciles de identificar en una pantalla pequeña.
7. Usuario que quiere resolver una operación rápidamente y podría frustrarse con explicaciones largas.
8. Persona que aprende mejor con ejemplos, pistas y repetición guiada.

## Situaciones para explorar

Analiza cómo cree cada perfil que usaría la aplicación para:

- Encontrar la explicación de una tecla científica en el índice.
- Comprender la diferencia entre pulsar una función y pulsar «Pruébalo».
- Practicar una operación como una raíz cuadrada, un logaritmo o un seno en grados.
- Elegir entre las etiquetas Casio, TI y Sharp.
- Entender para qué sirven las teclas SHIFT/función secundaria, el modo DEG/RAD y los paréntesis.
- Interpretar el resultado visual de una respuesta correcta o incorrecta.
- Pedir una pista, ver el procedimiento y continuar con el ejercicio siguiente.
- Usar la aplicación desde un móvil.

## Instrucción para la simulación

Haz que cada perfil describa una sesión plausible usando solo la información del material. Para cada situación, separa:

- Qué intentaría hacer primero.
- Qué cree que ocurrirá.
- Qué etiqueta, explicación o paso podría confundirle.
- Qué ayuda concreta le permitiría continuar.
- La gravedad del problema hipotético: alta, media o baja.
- La confianza de su observación: alta, media o baja.

Después, resume los tres cambios de diseño con mayor impacto potencial. Para cada cambio indica qué perfil lo necesita y qué prueba real permitiría confirmarlo.

No afirmes que el HTML se ejecutó, que se pulsaron botones ni que se verificó una operación dentro de la simulación. Si la información disponible no permite juzgar un punto, indícalo como “requiere prueba real”.

## Requisito de simulación sugerido

Simula una prueba cualitativa de comprensión de calculadoraprendizaje con usuarios virtuales de distintos niveles y marcas conocidas. Evalúa la facilidad para orientarse entre índice, explicación, ejemplo reproducible y ejercicio; la claridad de las funciones secundarias, los modos de ángulo y las teclas habituales; la adaptación a pantallas pequeñas; y la utilidad de las pistas y señales de acierto/error. Devuelve feedback en español, separado por perfil, con pasos que intentaría, confusiones hipotéticas, severidad y confianza. Termina con una lista priorizada de mejoras y una prueba verificable para cada una. Recuerda que se evalúa una descripción, no una ejecución interactiva: no presentes las opiniones simuladas como pruebas de funcionamiento.
